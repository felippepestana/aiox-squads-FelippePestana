# Critérios de transparência — checklist de referência

Para o agente `arquiteto-transparencia` e o checklist `conformidade-transparencia-checklist.md`.

## Transparência ativa obrigatória (LAI / LC 131 / LRF)
- Receitas e despesas detalhadas (empenho, liquidação, pagamento) — tempo real (LC 131)
- Licitações, contratos e convênios (datas, valores, partes)
- Folha de pagamento / remuneração nominal (sem dados sensíveis — LGPD)
- Diárias, passagens e obras públicas
- RREO (bimestral) e RGF (quadrimestral) — LRF art. 48/48-A
- Estrutura institucional, competências, horários e contatos
- Legislação municipal e Diário Oficial

## Transparência passiva
- e-SIC funcional (prazo 20 + 10 dias; recurso); registro e estatísticas

## Padrões técnicos
- Dados abertos em formato aberto (CSV/JSON/XML); catálogo (CKAN); dicionário de dados
- API documentada (OpenAPI 3.0)
- SIAFIC — padrão mínimo (Decreto 10.540/2020)
- Acessibilidade WCAG 2.1 AA / ABNT NBR 17225:2025
- Responsividade mobile; busca transversal; linguagem cidadã em sumários

## Avaliação (selos e notas)
- EBT — Escala Brasil Transparente (CGU): meta nota 10
- PNTP — selos Prata (75-84%), Ouro (85-94%), Diamante (95-100%)

## Cases de referência (boas práticas)
- Niterói/RJ — governança de dados, dashboards, API
- Sobral/CE — portal redesenhado, API de dados abertos
- São Paulo/SP — CKAN, APILIB, integração GeoSampa/e-SIC

## Referência — Porto Velho
- Portal atual com nota CGU ~9,4/10 e selo Diamante (PNTP).
- Lacunas típicas a endereçar: API formalmente documentada, dashboards interativos,
  conformidade WCAG AA, linguagem cidadã e busca unificada entre módulos.
